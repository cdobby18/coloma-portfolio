AIDLC: The Workflow at a Glance

Carl Joshua Coloma · November 2026 · 5 min read
Share LinkedIn ↗ Email

AI can write code faster than I can read it. That is the whole problem. Speed only helps if I can still explain what shipped, prove it works, and catch the failure before a user does. AIDLC — my AI-assisted development lifecycle — is the loop I use to keep that balance.

The workflow at a glance

Eight steps, one loop.

  1. Define the problem

    Write down the constraints, acceptance criteria, and risks before touching code. If I cannot say what “done” looks like, I am not ready to start.

  2. Choose the execution mode

    Direct execution for a small change. Plan mode for a larger one. The size of the change decides the ceremony — not the other way around.

  3. Implement in small, reviewable increments

    A coding agent can do the typing. I still read the diff, understand the design decisions, and own what lands.

  4. Require meaningful tests

    Not coverage theater. Tests that would actually fail if the behavior regressed.

  5. Run the full verification toolchain

    Lint, typecheck, unit tests, integration tests, and build. The same checks CI will run, run locally first.

  6. Review the diff locally, then again in a PR

    Local review catches the obvious issues early. The pull request is where the change becomes a shared artifact and someone else gets a chance to challenge it.

  7. Run a separate AI reviewer with fresh context

    A fresh reviewer sees what the author’s context has normalized. Valid comments go back to the coding agent — not into a backlog.

  8. Re-test, re-review, merge

    Merge only when CI, human review, and the final engineering bar all pass. A failed check sends the change back to the step that can fix it.

plan → implement → test → inspect → review → revise → verify

Why I work this way

I am early in my career. The fastest way to get better is to make my mistakes visible, fix them in the open, and keep a record of what changed. AIDLC is how I do that with AI in the loop: the agent can move fast, but the responsibility for the result stays with me.
